# Notes for Claude: David Okunlola's portfolio

David is a designer, not a developer. He maintains this site only by asking for changes. Explain every step in plain language, show changes locally before publishing, and when he has to do something in a dashboard, give exact clicks and wait for him.

## How the site is put together

- `site-source/pages/*.html`: one file per page, holding only that page's own content. Each starts with a `<!--page { ... } -->` block (path, title, description).
- `site-source/shared-parts/`: header, footer, the "Connect" paragraph (`contact-box.html`), page shell. Included with `{{> name}}`.
- `site-source/content/`: `site-details.json` (email, links, availability wording, the `showInSearchEngines` switch), `projects.json` and `case-studies/*.json` (only the projects that are NOT in Sanity: the confidential case study and the brand placeholder).
- **Sanity** holds the public case studies (project `j5ifj8rh`, dataset `production`, both in `site-details.json`). David edits them at https://davidokunlola.sanity.studio. `build-website.js` ("Content from Sanity") fetches every published `caseStudy` at build time and builds its page, home tile and Work list rows from it. Publishing in Sanity rebuilds the site automatically: a Sanity webhook named "Rebuild website" (filter `_type == "caseStudy"`) calls a Cloudflare Workers Builds deploy hook named "Sanity publish". The hook address is private and lives only in those two dashboards. `npx sanity hooks logs` in `sanity-studio` shows whether a delivery succeeded. The editor's code is `sanity-studio/` (its own `package.json`, React, not part of the site); field names in `sanity-studio/schemaTypes/case-study.js` must match `fromSanity()` in the build script. Below the fixed Overview, a case study is a free list of `sections` that David adds, names and reorders himself (kinds: `textSection`, `listSection`, `numbersSection`); `caseSection()` renders any of them, a section with nothing in it is skipped, and two or more pictures become a click-through gallery (stacked on tablets and phones). A section's `pictures` list also takes animated GIFs (Sanity keeps the animation when resizing) and MP4 videos (`_type: video`, a Sanity file asset), which `site.js` plays muted on a loop only while visible. A new kind of section needs a schema object, a line in `fromSanity()` and markup in `caseSection()`. After changing the fields, run `npx sanity deploy` in `sanity-studio` (needs David signed in with `npx sanity login`). The dataset is public on the free plan, so the confidential case study stays a local file (`content/case-studies/confidential-project.json`) and must not go into Sanity.
- `site-source/static/`: styles (`styles/site.css`, one file), scripts (`site.js` for interactions, `site-sounds.js` for sounds), images, icons, fonts. Copied as they are.
- `build-website.js`: zero-dependency Node script that assembles everything into `site-output/` (generated, not committed).
- `cloudflare-worker/`: the only server-side code. `confidential-project-lock.js` (password gate, secret `CONFIDENTIAL_PROJECT_PASSWORD`), `note-wall.js` (About page notes in D1, with spam limits) and `about-photos.js` (writes the photos from David's Google Drive folder into the About page and serves page-sized copies at `/photos/...`; secrets `PHOTOS_DRIVE_FOLDER` and `GOOGLE_DRIVE_API_KEY`; without them the built-in placeholder photos show). The Drive folder link must never appear in the repository or the pages.
- `wrangler.jsonc`: Cloudflare settings. `wrangler deploy` and `wrangler dev` both run the build first.

Keep it this simple: plain HTML, CSS and JavaScript, no framework, no bundler.

## Commands

- Preview: `npm run preview` (http://localhost:8787). New files under `static/` sometimes need the preview restarted before they are served.
- Build only: `npm run build`.
- Publish: commit and `git push origin main`. Cloudflare Workers Builds deploys every push. Check the result with GitHub's check-runs API for the commit (check name "Workers Builds: dave-o-portfolio").

## Conventions and decisions

- Design values come from the Figma file `Cxm2gOunARq7PacIRj2qfv`, section "Main Design for my portfolio - Corrected" (node 303:1782). Token names follow the Radian design system.
- Several parts were built from David's direct requests and reference sites rather than Figma: the pinned picture stage on case studies, Kind words, the exploration shortlist and tile grid, the Connect paragraph, sounds, the logo, the note wall. If Figma and the site differ on these, ask him which is current.
- Placeholder text in square brackets is shown on purpose until he supplies real content. Search engines: `showInSearchEngines: false` keeps the site hidden as a whole, but pages are opened one by one (`listedInSearch()` in the build script). A Sanity case study is listed automatically once it has a search description and no square-bracket placeholder text, unless `hideFromSearch` is ticked; any other page needs its address in `pagesShownInSearchEngines` in `site-details.json`, which David must ask for. Listed pages go in `sitemap.xml`; hidden ones get a noindex tag and a `_headers` rule. Do not open a page that still shows placeholders.
- Never invent testimonials, results or biography. Ask him for the real text.
- Phone navigation (up to 767px) is a bottom sheet from Figma node 401:6959: the same `.site-nav` element as the desktop row, restyled, with a blurred backdrop, a pull-down handle and a close button that exist only on phones. Opening and closing it fires `haptic()` in `site.js` (vibration on Android; a hidden switch flip on iPhone, since Safari has no vibration). The speaker button in the phone header is not in that Figma frame and was kept on purpose. Tapping Work inside the sheet does not leave the page: it shows the Product design projects one at a time (Figma node 410:7413, built by `sheetWorkProjects()` in the build script), with View case study and Next buttons; the sheet is at most 520px tall and the project details scroll inside it. On tablets and desktop Work still goes to `/work/`.
- Breakpoints: phones up to 767px, tablets 768 to 1099px, desktop 1100px and up. Check all three, and check for sideways scrolling.
- Visitor statistics: Cloudflare Web Analytics and Microsoft Clarity, loaded by `static/scripts/site-analytics.js` only when `cloudflareAnalyticsToken` / `clarityProjectId` are filled in `site-details.json`. David chose both tools; running Clarity without cookies (so no consent banner) and keeping it off the confidential case study was Claude's recommendation. Ask before adding cookies or a banner.
- `wrangler dev` does not reliably pick up edits to `cloudflare-worker/*.js`; restart the preview after changing them. Its local cache lives in `.wrangler/state/v3/cache`.
- The user-facing guide is `HOW-TO-UPDATE-THIS-SITE.md`. Keep it accurate when the workflow changes.
